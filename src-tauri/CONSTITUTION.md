## 第 1 部分：项目规则与约束

### 1. 项目名称与定位

- 项目名称：Metheus（弥）。
- 核心定位：面向复杂软件任务的桌面编译与执行系统，把用户目标经过讨论、确定性检查、计划、批准、受控执行和验证，转化为可检查、可恢复的代码变更。
- 目标用户：需要在本地项目中规划和实施复杂变更，同时保留人工决策、文件范围、安全凭据和稳定回退边界的个人开发者、产品人员和技术用户。
- 产品不是无边界的一键自动编程工具。自动化只能在用户已批准的目标、计划、执行引擎配置和文件范围内运行。

### 2. 技术栈与运行边界

- 桌面壳：Tauri 2。
- 后端：Rust。业务逻辑、项目文件访问、进程管理、Git 操作、模型请求和执行引擎调用均由 Rust 侧负责。
- 前端：React 19 + TypeScript，使用 Vite 7 构建；单页工作流不引入路由库。
- 现有前端交互依赖：Radix Dialog、Tabs、Tooltip 和 Lucide。已有对应能力时应复用现有组件，不手写平行实现。
- 决策模型：经 Rust 后端调用可配置的 OpenAI Compatible 接口，用于讨论、检查、规划和审查；前端不得直接调用模型 API。
- 执行引擎：统一经过 `engine/` 适配层。插件模式支持 Claude Code、Codex、Kimi CLI 和 Grok Build CLI；内置模式只允许受控 Grok Build 运行时，并受编译特性、受控 Fork 和自检边界约束。
- 持久化使用本地 JSON 和系统凭据库，不引入前端数据库或直接文件访问能力。

### 3. 架构与事实源

- 前端只负责 UI、用户交互和后端事实的展示。所有文件访问、外部 API、模型请求、执行进程和 Git 操作必须通过 Tauri IPC 调用 Rust 后端。
- `src-tauri/src/lib.rs` 是后端入口，负责应用状态、基础持久化能力和 Tauri command 注册；业务规则按领域模块维护。
- `project.rs` 定义项目数据结构，前端 `types.ts` 的对应结构必须与其保持兼容。
- 后端持久化并重新读取的完整 `Project`、`WorkflowState`、执行会话和命令结果是项目业务事实。前端不得以临时对象、错误文本、局部字符串或完整项目覆盖伪造状态转换。
- 前端应用异步结果前必须核对项目身份和数据修订；旧响应不得覆盖新事实。
- 执行引擎健康、自检缓存和认证验证是应用级事实，不得写入 `Project` 或伪装成项目业务事件。
- 不引入 WebSocket 等远程进程通信协议；桌面进程内状态同步使用 Tauri IPC、Channel 或等价的应用级通知。

### 4. 工作流、审批与执行边界

- 统一工作流状态是业务页面和操作权限的判断依据。旧兼容字段只能用于兼容或视觉展示，不能裁决关键业务动作。
- 讨论、三项检查、项目方案、阶段计划和执行计划必须按后端状态机推进；检查失败、信息不足、契约冲突或未批准时不得进入下一步。
- 决策模型只生成受结构化契约约束的讨论、计划和审查结果；实际代码变更只能由执行引擎在批准后的任务中实施。
- 手动模式保留逐步批准与确认。Managed Flow 和 autopilot 只能代点已有的合法后端动作，不得绕过检查、批准、精确文件范围、质量门禁、Git 安全边界或大阶段 A/B/C 人工决策。
- 执行开始后冻结执行配置、设置修订、模型/接口指纹和可执行程序事实；恢复链路必须沿用同一会话快照，不得静默切换引擎或新配置。
- 执行引擎健康必须 fail-closed。未安装、未认证、版本不兼容、待在线验证、验证失败、禁用或配置无效时禁止启动执行。
- 每个任务只能修改批准的精确文件路径。信息不足、发现范围外问题或产生越权修改时必须停止并报告，不得扩展架构或修改相邻文件。
- 自动修复、重试和重规划必须有明确次数与无进展停止条件；测试不可用、重复失败、范围冲突或需要人工判断时进入明确的人工作业出口。

### 5. 数据、设置与密钥安全

- 项目事实由 Rust 后端持久化到 `~/.metheus/{project_name}.json`；关键命令必须先持久化，再返回可从磁盘确认的完整事实。
- 非敏感应用设置保存到 `~/.metheus/config/app-settings.json`，并使用修订号防止旧写覆盖新设置。
- 决策模型、内置 Grok Build 和视觉模型密钥不得写入项目文件、应用设置 JSON、执行会话、日志、错误文本或前端持久状态。
- 密钥优先保存到系统凭据库，或在允许的目标上由用户明确选择仅本次会话使用。环境变量只作为已定义目标的兼容回退，不能作为唯一或强制来源。
- 决策请求和执行操作的活动租约必须覆盖真实后端生命周期；活动租约存在时拒绝修改设置，前端等待超时不得清除或猜测租约状态。
- 文件列表、文件内容和预览必须由 Rust command 提供，并验证项目根、规范路径、路径逃逸、符号链接逃逸、内容大小、编码和二进制边界。前端不得直接读取或写入项目文件。
- 发送给外部模型的上下文必须限于当前任务所需的最小范围。不得无必要地发送完整项目宪法、密钥、用户隐私、无关文件或未批准的项目内容。

### 6. 依赖与前端实现规则

- 允许继续使用已安装的 Radix UI 交互组件和 Lucide 图标；纯图标操作必须有可访问名称或 Tooltip。
- 新增 Cargo 或前端依赖前必须说明用途、许可证、是否引入远程通信能力，以及是否显著增加二进制体积。禁止商业闭源依赖和与项目许可证不兼容的依赖。
- 不引入 Redux、Zustand、MobX 等复杂状态管理库替代后端事实源；优先使用现有 React 状态、策略模块和后端状态模型。
- 不在前端引入路由库、网络请求库、Node.js 原生模块、数据库驱动或完整主题/UI 框架来绕过现有 Tauri/Rust 边界。
- 不得为了简化 UI 而吞掉错误、伪造成功、降低引擎健康门禁或隐藏需要用户处理的状态。

### 7. 变更一致性与禁止事项

- 修改后端数据结构时，必须同步核对前端类型、序列化兼容和旧项目读取路径。
- 修改命令、审批或恢复流程时，必须保持后端状态机、持久化最终事实和前端权限展示一致。
- 禁止前端直接读写本地文件、调用外部 API、启动执行进程或持久化敏感密钥。
- 禁止任何 AI 或自动驾驶流程绕过用户批准、工作流检查、文件授权、执行引擎健康或人工决策边界。
- 禁止硬编码 API Key、把密钥写入 `.env` 作为项目持久化方案，或在日志和错误中回显密钥。
- 禁止业务模块绕过 `engine/` 直接拼装具体执行引擎参数或直接依赖内置 Grok 实现。
- 禁止把未经当前代码或用户批准确认的临时状态、视觉偏好和推测写成长期项目事实。
